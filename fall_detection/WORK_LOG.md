## 二、工作时间线

### Day 1（7-26）：真实数据训练打通

1. **AV1 解码问题**：OmniFall 视频包是 AV1 编码，OpenCV 无法解码。
   解法：`prepare_data.py` 新增 `_iter_frames()`，cv2 失败时回退 imageio-ffmpeg rawvideo 管道解码。
2. **数据分层抽样**：发现 tar 内视频按类别目录字典序排列，直接取前 N 个会全是 fall 类。
   改为按 10 个动作类别配额抽样（fall 24% / fallen 16% / 其余均分），自然覆盖相机俯仰角/方位角/距离。
3. **500 视频首次真训**：~3500 序列，50 epochs。结果：recall 0.635 / AUC 0.740。
   对比用户 Windows 机旧代码训练（数据量 10 倍）：F1 略低但 recall +12 点（Focal alpha 0.25→0.75 的效果）。
4. **报警阈值标定**：`tcn_prob_threshold` 0.2→0.4（原 0.2 是为合成模型低输出专门调低的），test/ 4 段首次全对。

### Day 1 晚：跟踪器重大 bug 修复（本轮最大单项收益）

`pipeline/tracker.py` 三个叠加 bug 导致 **160 帧产生 93 个跟踪 ID**（同一个人被切得粉碎，TCN 永远看不全动作）：

| Bug | 原状 | 修复 |
|---|---|---|
| 匹配阈值过严 | IoU ≥ 0.8 才算同一人 | 0.8 → 0.3 |
| 新 track 无匹配资格 | `_get_active_tracks` 要求 `age > 0` | 删除该条件 |
| 二次匹配误标丢失 | `matched_trk_ids` 漏算低分框匹配 | 补全 + 修正索引语义（列表索引≠track_id） |

修复后 ID 数 93→3，**红外场景跌倒检出 0/2 → 2/2**，全场景概率普遍上升。

### Day 1 深夜：长尾场景体系

- **评测**：新建 `eval_longtail.py`，生成微光/红外风格/遮挡三种变体 × 5 场景自动对比
- **训练侧增强**（`data/augment.py`）：burst 式整帧检测丢失（模拟 YOLO 整帧漏检）、半入境截断增强（负样本下半身置零）、IR 结构化退化增强、关键点抖动/丢弃
- **推理侧**：亮度自适应低光增强（均值 <60 才触发 gamma+CLAHE，亮帧零开销）；关键点完整性门控（可见关键点 <50% 的帧不喂 TCN，治半入境误判）；概率时序平滑（3 帧均值）

### Day 2（7-27 凌晨）：扩数据重训 + 封版

1. **2000 视频重训**：~14000 序列（4 倍），叠加全部改进。
   帧级：recall 0.737 / AUC 0.819 / F1 0.627，对比 500 版全面 +8~10 点。
2. **阈值调优工具**：`tune_threshold.py` 在 val 集扫描 P/R/F1 曲线，输出最佳工作点（文档素材）。
3. **难负样本加权**：用躯干角变化幅度识别"坐下/躺下"类难负样本，采样权重 1–4 倍。
4. **手部支撑特征**（用户提出的生物力学先验 FOOSH）：手腕速度 4 维 + 贴地度 + 支撑分，
   填入运动特征编码器原有的 11 维 padding 空位，48 维输入不变、导出格式不变。
5. **IR 攻关（未完全解决，如实记录）**：
   - 尝试 1：IR 退化增强 25% 重训 → RGB 场景回归（elderly 误报、fall-05 漏报），回退
   - 尝试 2：bbox 横躺规则 + 动态规则记忆 → 引入 elderly 回归，回退
   - 根因诊断：TCN 概率峰值比投票窗口填满早 4 帧（时序错位）+ IR 下躯干角特征退化
   - **结论**：小测试集上继续调参 = 过拟合，停止。IR 定性为已知边界，需真实红外数据标定
6. **速度阈值重新标定**：0.02 → 0.03。发现旧阈值是在跟踪器 bug 时期标定的
   （ID 碎片使速度测量值趋零），跟踪修好后真实速度恢复：真跌倒 0.09–0.16、
   慢速跌倒 0.032、缓慢坐地尖峰 0.028，0.03 分离。

## 三、重要教训（写入团队知识库）

1. **管线测试必须显式加载 checkpoint**：`FallDetectionPipeline()` 不传模型会用随机权重，
   且随机权重在规则引擎配合下会产生"看似合理"的结果，一度误导出"ADL 误报"的错误结论。
2. **阈值要随组件修复重新标定**：速度阈值 0.02 是在跟踪器 bug 时期定的，
   组件修好后旧标定全部失效——修完底层组件要重审所有下游阈值。
3. **小测试集调参陷阱**：4~9 段视频上做阈值排列组合必然过拟合，
   指标冲突时（fall-05 vs elderly）应回到数据/模型层解决，而非继续拧阈值。
4. **增强不是越多越好**：IR 退化增强 25% 概率直接拉垮 RGB 性能，
   增强分布与目标场景分布不匹配时先小规模验证再全量重训。
